# knowledge-share-app（ナレッジ保存）

気になった記事を、Androidの共有シートから **3タップ** でGoogle Driveにカテゴリ別ストックする個人用ツールです。
LINE WORKS掲示板で行っていた「URL+一言コメントのカテゴリ別ストック」運用の移行先で、保存先がDriveなのでAI(Claude)からも直接参照できます。

**操作の流れ（実機）**
1. ブラウザの共有ボタン（⤴）をタップ
2. 共有先から「ナレッジ」を選択
3. カテゴリボタンをタップ → 自動保存 → 画面を閉じる

保存されるもの:
- Googleドキュメント: `マイドライブ/ナレッジ/<カテゴリ名>/記事タイトル_YYYY-MM-DD`（タイトル・URL・保存日時・カテゴリ・**本文の自動抽出テキスト**、共有時のコメントがあればメモとして記録）
- 検索用インデックス: `マイドライブ/ナレッジ/ナレッジ一覧`（Googleスプレッドシート）に、保存の都度「日時・カテゴリ・タイトル（クリックで記事を開けるリンク付き）・URL・メモ・Driveファイル（ドキュメントへのリンク）」を1行追記

> 共有元が `share.google` 等の短縮/リダイレクトリンクを渡してきた場合は、保存前に実際の記事URLへ自動解決してから保存します（元の短縮URLは「共有時のURL」として参考記録）。これにより、AI(Claude)がDrive上のファイルを直接読むだけで記事の内容・実URLの両方を把握できます。
>
> **保存形式について**: 当初はプレーンテキスト/Markdown（`.md`）で保存していましたが、クラウド版Claudeの Google Drive 連携（自然言語での自動読み込み）が対応するファイル形式に text/markdown・text/plain が含まれておらず、AIがファイルを直接開けない（スクリーンショット等の代替手段が必要になる）ことが実運用で判明したため、Googleドキュメント（`DocumentApp`）ネイティブ形式に変更しました。内容自体はこれまで通りMarkdown記法の文字列をそのままドキュメント本文に流し込んでいるため、見た目上は `#` 等の記号が残るプレーンテキスト表示になりますが、AI・人間どちらにも構造は読み取れます。

## 構成

| レイヤー | 実体 | 役割 |
|---------|------|------|
| フロントエンド | `index.html` + `manifest.json` + `sw.js`（PWA） | Web Share Target APIで共有シートに登録。カテゴリ選択・一覧閲覧・カテゴリ管理UI |
| バックエンド | `gas/Code.gs`（GAS Webアプリ） | タイトル自動取得・Drive保存・Sheetsインデックス追記・カテゴリ管理API |
| ホスティング | Vercel（静的配信） | PWAはHTTPS配信が必須のため |

```
knowledge-share-app/
├── index.html            # PWA本体（1枚のHTML）
├── manifest.json         # share_target 定義を含むPWAマニフェスト
├── sw.js                 # サービスワーカー（インストール要件用の最小実装）

```

## セットアップ手順

### Step 1: GAS（バックエンド）のデプロイ

1. [script.google.com](https://script.google.com) で「新しいプロジェクト」を作成（名前例: ナレッジ保存API）
2. エディタで、最初から入っている `function myFunction() { }` を**全て削除**してから、`gas/Code.gs` の内容を貼り付けて保存（Ctrl+S）
   - ⚠️ よくある失敗: デフォルトの `myFunction` の中括弧 `{ }` の**内側**に貼り付けてしまうと、`doGet`/`doPost` が正しく認識されません。貼り付け後、関数選択のプルダウンに `doGet` `doPost` が並ぶか確認してください
3. 合言葉を設定する（推奨。URLを知られても第三者に書き込まれないための簡易保護）
   - 左メニュー「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」
   - プロパティ: `SHARED_TOKEN` ／ 値: 好きな合言葉（例: ランダムな英数字）
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（合言葉で保護する前提。Googleアカウント制限にするとPWAからのfetchが通らないため）
5. 「デプロイ」を押し、権限承認ダイアログで**「Select all」にチェックして**承認
   - 要求される権限: Google Driveへのフルアクセス（記事保存・Sheets/Docs作成）、外部サービスへの接続（記事タイトル・本文取得）
6. 表示された **WebアプリURL**（`https://script.google.com/macros/s/…/exec`）を控える

動作確認: WebアプリURLをブラウザで開き `{"ok":true,...}` が表示されればOK。

> コードを修正したら「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で更新する（URLは変わらない）。**Sheets/Docs関連の機能を追加した際にOAuthスコープが増えているため、既存デプロイからの更新時は再度権限承認画面が出ます。「Select all」で承認してください。**

### Step 2: PWA（フロントエンド）のVercelデプロイ

1. [vercel.com](https://vercel.com) にGitHubアカウントでログイン
2. 「Add New…」→「Project」→ このリポジトリ（`knowledge-share-app`）を検索
   - 一覧に出ない場合: インポート画面の「Adjust GitHub App Permissions」（または [GitHubのInstalled Apps設定](https://github.com/settings/installations)）から、VercelのGitHub Appにこのリポジトリへのアクセスを許可する（非公開リポジトリでもデプロイ自体は可能。表示されないのは単にアクセス権の問題）
3. Framework Preset は「Other」のまま、設定変更なしで「Deploy」（ビルド不要の静的サイト）
4. 発行されたURL（`https://….vercel.app`）を控える

> 以後は `main` にプッシュするたび自動デプロイされます。

### Step 3: 実機（Pixel 9a）でのインストールと共有シート登録

1. Chromeで Step 2 のURLを開く
2. 初回起動時に設定画面が出るので入力して「保存する」
   - GAS WebアプリのURL: Step 1-6 のURL（**共有先に表示される他アプリのURLではなく、必ずGASのWebアプリURLを入れる**）
   - 合言葉: Step 1-3 で設定した値
3. Chromeのメニュー（⋮）→「**ホーム画面に追加**」→「**インストール**」を選択
   - ※「ショートカットを追加」ではなく「インストール」であること。インストール型で入れると共有シートに登録される
4. インストール後、適当な記事ページで共有ボタン（⤴）→ 共有先一覧に「**ナレッジ**」が出ることを確認
   - 出ない場合: 一覧を左にスクロール／「その他」を開く。それでも無ければ一度アプリを開いてから再確認

### 実機での投稿テスト

1. Chromeで任意の記事を開く → 共有（⤴）→「ナレッジ」
2. 画面上部に「検出したタイトル（参考）」と保存対象のURLが表示されることを確認
3. カテゴリボタン（例: PC系）をタップ
4. 「保存しました！」表示を確認
5. Google Driveの `ナレッジ/PC系/` に `記事タイトル_YYYY-MM-DD`（Googleドキュメント）ができていること、`ナレッジ/ナレッジ一覧`（スプレッドシート）に1行追記されていることを確認

## 画面の機能

| ヘッダーアイコン | 機能 |
|---|---|
| 📁 | Driveの「ナレッジ」フォルダを新しいタブで直接開く |
| 📋 | カテゴリ別の保存済み記事一覧を表示（タップで元記事を新しいタブで開く／各記事の「編集」でタイトル・URL・メモを修正） |
| ⚙ | GAS接続設定・カテゴリの追加/削除/並び替え |

### PCブラウザからの利用
Androidの共有シート（Web Share Target）はPCでは機能しないため、PCでは共有パラメータ無しで開いたときに表示される**URL・メモの手入力欄**から新規保存します。カテゴリ選択・一覧閲覧・記事編集はスマホと共通で、画面幅が広いときはレイアウトが横長向けに調整されます（メディアクエリ分岐。スマホ表示は従来のまま）。

## カテゴリの管理

カテゴリは固定配列ではなく、GAS側のスクリプトプロパティで動的に管理しています（PWAは起動時にGASから取得）。

- **初期値**: LINE WORKS掲示板の構成を踏襲した10件（業務マニュアル／自由掲示板／PC系／DTP系／その他PC学習、スキル／PCニュース／語学系／英語・中国語／レシピ、お店／TOCO/お知らせ）。GASへの初回アクセス時に自動でこの初期値が設定されます
- **追加・削除**: 設定画面（⚙）の「カテゴリ管理」から行えます。コード変更もGASの再デプロイも不要です
- **並び替え**: 設定画面（⚙）の「カテゴリ管理」の ↑/↓ ボタンで表示順を変更できます。並び順はGAS側に保存され、保存画面・一覧画面のカテゴリボタンにも同じ順序で反映されます。新規追加カテゴリは従来どおり末尾に付きます
- **削除の挙動**: カテゴリ選択肢から外れるだけで、Drive上の保存済みファイルやSheetsの過去の行は削除されません（非破壊）
- **改名は未対応**: 名前を変えたい場合は「新しい名前を追加」→「古い名前を削除」で代用してください（過去のデータは旧カテゴリ名のまま残ります。Driveのフォルダ名は手動でリネームすれば追随できます）

## Vercel Serverless Function（Claude検索用API）

Claude.ai（`web_fetch`）から、GASの記事検索API（一覧・横断検索・カテゴリ取得）を直接叩けるようにするための中継APIです。GASのWebアプリURLと合言葉(`SHARED_TOKEN`)をClaude.ai側に渡さずに済むよう、Vercel側の環境変数として保持し、リクエストのたびにサーバー側で付与してGASへ転送します。

### 環境変数（Vercelダッシュボードで設定）

値そのものはこのリポジトリ・READMEには記載しません。

| 変数名 | 用途 |
|---|---|
| `GAS_URL` | GAS WebアプリのURL（[Step 1](#step-1-gasバックエンドのデプロイ)でデプロイしたexec URL） |
| `SHARED_TOKEN` | GAS側の `SHARED_TOKEN`（スクリプトプロパティ）と同じ合言葉 |

**設定手順**
1. Vercelのプロジェクトダッシュボード → 「Settings」→「Environment Variables」
2. 「Add New」で `GAS_URL` と `SHARED_TOKEN` をそれぞれ追加（Value欄に実際の値を入力、対象環境は Production 等必要な範囲を選択）
3. 保存後、「Deployments」タブから最新デプロイの「Redeploy」を実行（環境変数は次回デプロイから反映されるため）

### API仕様

```
GET /api/knowledge?action=<list|search|categories>&keyword=<任意>&category=<任意>&offset=<任意>
```

GASの `doGet` にあるクエリパラメータをそのまま転送するだけの中継です（`token` はクライアントから受け取らず、サーバー側で付与）。

| パラメータ | 必須 | 説明 |
|---|---|---|
| `action` | ○ | `list`（カテゴリ内一覧）／`search`（カテゴリ横断キーワード検索）／`categories`（カテゴリ・タグ一覧取得） |
| `keyword` | - | `list`／`search` の絞り込みキーワード（タイトル・メモ・タグの部分一致） |
| `category` | `list`のみ必須 | 対象カテゴリ名 |
| `offset` | - | ページング開始位置（`list`／`search` のレスポンスの `hasMore`/`offset` に従って次ページ取得に使う） |

レスポンスはGASの応答（`{ ok: true, ... }` / `{ ok: false, error: ... }`）をそのまま透過します。

**動作確認URL例**（`<vercelのデプロイURL>` は実際のものに置き換え。token は含めません）
```
https://<vercelのデプロイURL>/api/knowledge?action=categories
https://<vercelのデプロイURL>/api/knowledge?action=search&keyword=Docker
```

エラー時のレスポンス:
- 環境変数(`GAS_URL`/`SHARED_TOKEN`)未設定: HTTP 500
- GASへの通信自体に失敗（ネットワークエラー等）: HTTP 502
- GAS側が業務エラー（`ok: false`）を返した場合: HTTP 200 のまま `{ ok: false, error: ... }` を透過（GASのWebアプリはHTTPステータスを持たず常に200で応答するため）

## 設計メモ

- **認証**: GASは「全員」公開 + スクリプトプロパティ `SHARED_TOKEN` の合言葉照合による簡易保護。個人利用前提の最小構成（本格的な認証基盤は意図的に持たない）。保存・カテゴリ変更(POST)だけでなく、**記事一覧・カテゴリ取得(GET)も合言葉必須**（一覧はタイトル・URL・メモといった個人の閲覧記録に近い情報を含むため、WebアプリURLを知られただけでは読めないようにしている。稼働確認のみ合言葉不要）
- **CORS**: PWA→GASの通信は、POSTは `Content-Type: text/plain` で送ることでプリフライト(OPTIONS)を回避し（GASはOPTIONSに応答できない）、GETはヘッダを付けないシンプルリクエストとして送る
- **URLの受け取り**: Androidの共有シートはアプリによってURLを `url`/`text`/`title` のどこに入れるかが揺れるため、`shared_url` → `shared_text` → `shared_title` の順で探索。`shared_text` のURL以外の部分は記事タイトルの参考表示・保存時のメモの両方に使う
- **タイトル取得のフォールバック**: 通信失敗・HTTP 4xx/5xx・`<title>` 不在時は og:title → URLそのもの、の順で代替
- **ファイル名**: `記事タイトル_YYYY-MM-DD.md`。タイトルを先頭にしているのは、Driveの一覧表示（幅が狭いと末尾が省略される）で日付に隠れず記事内容がひと目でわかるようにするため。Windows禁止文字を除去、60文字で切り詰め、同名衝突時は時刻を付与して上書き回避
- **検索用インデックス（Sheets）**: Googleドキュメント（Drive）を正本としつつ、人間・AIが検索・一覧しやすいようGoogleスプレッドシートにも同時記録する二層構成。タイトル列は元記事URLへの、Driveファイル列は保存したドキュメントへの `HYPERLINK` 数式にしており、Sheets上でタップすると開く。ドキュメント本体を直接検索・特定できるため、Driveの全文検索インデックス反映を待つ必要がない。インデックスへの追記が失敗しても、ドキュメント本体の保存自体は成功として扱う（検索補助であり本体ではないため）
- **カテゴリのCRUD・並び順**: `PropertiesService`（スクリプトプロパティ）にJSON配列として保存（配列の順序＝表示順）。追加・削除・並び替えはGASへのPOST(`action=addCategory`/`removeCategory`/`reorderCategories`)で行い、`SHARED_TOKEN` の検証対象にも含まれる。並び替えは「現在の一覧の並べ替えになっているか」を検証してから保存する
- **保存済み記事の編集**: `action=update`（POST・`SHARED_TOKEN`検証あり）で、GoogleドキュメントのfileIdを一意キーに Sheetsインデックスの該当行（タイトル/URL/メモ）とドキュメント本文を更新する。fileIdはSheetsの「Driveファイル」列のHYPERLINK数式（`getFormulas`で取得）から抽出し、一覧APIが各記事に付与する。行特定は**Sheetsインデックスに載っている記事に限定**し（一覧に無いfileIdは拒否）、無関係なDriveファイルを触らせない。保存日時・カテゴリ・自動抽出された本文・「共有時のURL」行は編集時も保持する。タイトル/URLはHYPERLINK再構築、メモは `sanitizeCellText_` で数式インジェクション対策を適用（saveと同方針）
- **保存の体感高速化（fire-and-forget）**: GAS側のタイトル取得〜Docs保存は20〜30秒かかるため、PWAは応答を待たずに送信した時点で「保存しました」を表示する。fetchの `keepalive: true`（非対応環境は `navigator.sendBeacon`）により、表示直後にアプリを閉じても送信はOS/ブラウザが完了させる。検知できるのは送信自体の失敗（オフライン等）のみで、その場合はエラー画面を表示する
- **表示キャッシュ（stale-while-revalidate）**: カテゴリ一覧と記事一覧（各カテゴリの先頭ページ）を `localStorage` にキャッシュし、画面表示時はまずキャッシュで即描画→裏でGASから最新を取得して差分があれば描き直す。初回（キャッシュ無し）のみ取得完了を待つ
- **記事一覧のページング**: 一覧APIは新しい順に50件ずつ返し（`offset` パラメータで続きを取得、`hasMore` で継続有無を返す）、PWAは「さらに読み込む」ボタンで追記表示する
- **ルートフォルダIDのキャッシュ**: 「ナレッジ」フォルダを毎回名前検索せず、初回に見つけたIDをスクリプトプロパティに記憶してIDで直接開く（カテゴリ・一覧APIの応答高速化。フォルダが削除されていた場合は名前検索で作り直す）
- **短縮/リダイレクトURLの解決**: 保存前に `UrlFetchApp`（`followRedirects: false`）で3xxレスポンスの`Location`ヘッダを最大5回まで手動で辿り、実際の記事URLを特定する。解決できない場合は元のURLのまま保存する（エラーにはしない）
- **本文の自動抽出**: `<script>`/`<style>`/コメントと非本文の構造要素（`<nav>`/`<header>`/`<footer>`/`<aside>` = メニュー・ランキング・フッター等）を除去したうえで、`<article>` または `<main>` があればその中身だけを対象にし、ブロック要素の境目で改行を入れてからタグを剥がすHTML→テキスト変換。最大4000文字で打ち切り。**Readability相当の高度な本文判定ではない**ため、セマンティックタグの無いサイトでは本文以外のテキストが混入することがある
  - **既知の制限**: X(Twitter)のようにJavaScriptでの動的描画に依存するサイトは、`UrlFetchApp`が取得する初期HTMLに本文が含まれないため、タイトル程度しか取れないことが多い
- **Sheetsへの書き込み安全策**: タイトル・メモ等の自由入力由来のセル値は、先頭が `=` や `+` の場合にアポストロフィを付けて書き込む（GASの `appendRow` は先頭 `=` の文字列を数式として解釈するため、悪意あるページタイトル経由の数式実行を防ぐ）
- **一覧画面のXSS対策**: 記事一覧はHTML文字列の結合ではなくDOM API（`createElement` + `textContent`/`href`プロパティ）で描画する（URL内の引用符による属性breakoutを構造的に防ぐ）。hrefに設定する前にURLスキーム（http/https）も検証する
- **メモの重複防止**: Android共有時、共有テキストの「URL以外の部分」がタイトルと同一の文字列になることが多い（共有元がタイトルをそのままテキストに乗せてくるケース）。GAS側で実際に取得したタイトルと完全一致する場合はメモとして保存しない
- **保存形式（Google Docs）**: `DocumentApp.create()` で作成し、Sheetsインデックスの作成と同様に既定の作成先（マイドライブ直下）からカテゴリフォルダへ `addFile`/`removeFile` で移動する。本文はMarkdown記法の文字列をそのまま `Body.setText()` で流し込む素朴な実装で、リッチテキスト変換（見出しスタイル等）は行わない
  - **既知の制限**: この変更より前（プレーンテキスト/`.md`時代）に保存済みのファイルは自動移行されない。クラウド版Claudeから内容を読ませたい場合は、実機から該当記事を再共有すれば新形式（Googleドキュメント）で保存し直せる
