# knowledge-share-app（ナレッジ保存）

気になった記事を、Androidの共有シートから数タップでカテゴリ別にストックする個人用ツールです。
LINE WORKS掲示板で行っていた「URL+一言コメントのカテゴリ別ストック」運用の移行先で、保存先がGoogleスプレッドシートなのでAI(Claude)からも直接参照できます。

**操作の流れ（実機）**

1. ブラウザの共有ボタン（⤴）をタップ
2. 共有先から「ナレッジ」を選択
3. （任意）メモを編集する・タグを選ぶ
4. カテゴリボタンをタップ
5. 「この内容で保存」をタップ → 「保存中です」表示 → 画面を閉じる（✕）か、そのまま次の保存へ

保存されるもの:

- **検索用インデックス**: `ナレッジ一覧`（Googleスプレッドシート）に、保存の都度1行追記されます

| 列 | 内容 |
|---|---|
| 日時 | 保存日時（`yyyy-MM-dd HH:mm`・Asia/Tokyo） |
| カテゴリ | 選択したカテゴリ名 |
| タイトル | 自動取得したページタイトル（クリックで記事を開ける `HYPERLINK` 付き） |
| URL | 記事URL（短縮/リダイレクトリンクは実URLへ解決済み） |
| メモ | 共有時のテキストまたは手入力したメモ（任意） |
| Driveファイル | **現在は常に空**（後述の「Googleドキュメント保存の廃止」を参照） |
| タグ | 選択したタグを `, ` 区切りでまとめたもの（任意・複数可） |

> 共有元が `share.google` 等の短縮/リダイレクトリンクを渡してきた場合は、保存前に実際の記事URLへ自動解決してから記録します（最大5ホップ）。

> **Googleドキュメント保存の廃止について**: 以前は記事ごとに Drive へファイル（プレーンテキスト `.md` → Googleドキュメント）を作成し、ページ本文の自動抽出テキストも保存していましたが、現在は廃止し、**スプレッドシートのインデックス1行のみ**を保存する構成になっています。したがって記事本文はどこにも保存されません。過去にドキュメントとして保存済みの記事は Drive にそのまま残っており、`マイドライブ/ナレッジ/<カテゴリ名>/` から参照できます。

## セットアップ手順

### Step 1: GAS（バックエンド）のデプロイ

このスクリプトは検索用インデックスのスプレッドシートに**コンテナバインド**されている前提です（`SpreadsheetApp.getActiveSpreadsheet()` でバインド先を直接参照します）。script.google.com から単独プロジェクトとして作ると動きません。

1. Googleドライブでスプレッドシートを新規作成し、名前を **`ナレッジ一覧`** にする
   - 置き場所はどこでも動きますが、`マイドライブ/ナレッジ/` の中がおすすめです（📁ボタンで開くフォルダと揃うため）。`ナレッジ` フォルダはアプリの初回アクセス時に自動作成されるので、先に手で作っても構いません
   - シート（タブ）は1枚目が使われます。見出し行はアプリからの初回アクセス時に自動で書き込まれるので、空のままで構いません
2. そのスプレッドシートのメニューから「拡張機能」→「Apps Script」を開く（＝バインド済みプロジェクトが開く）
3. エディタで、最初から入っている `function myFunction() { }` を**全て削除**してから、`gas/Code.gs` の内容を貼り付けて保存（Ctrl+S）
   - ⚠️ よくある失敗: デフォルトの `myFunction` の中括弧 `{ }` の**内側**に貼り付けてしまうと、`doGet`/`doPost` が正しく認識されません。貼り付け後、関数選択のプルダウンに `doGet` `doPost` が並ぶか確認してください
4. 合言葉を設定する（推奨。URLを知られても第三者に読み書きされないための簡易保護）
   - 左メニュー「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」
   - プロパティ: `SHARED_TOKEN` ／ 値: 好きな合言葉（例: ランダムな英数字）
5. **権限承認を先に通しておく**（重要）
   - GASの権限承認は「そのサービスを使うコードが初めて実行されるとき」に要求されますが、Webアプリ（PWAからのfetch）経由では承認ダイアログを出せずに静かに失敗します
   - エディタに次の関数を一時的に追加し、関数プルダウンで `authorizeOnce` を選んで ▶実行 → 承認ダイアログを「Select all」で承認してください（実行後、この関数は削除して構いません）

     ```javascript
     function authorizeOnce() {
       DriveApp.getRootFolder().getName();               // Drive（「ナレッジ」フォルダ参照）
       SpreadsheetApp.getActiveSpreadsheet().getName();  // Sheets（インデックス追記）
       UrlFetchApp.fetch('https://example.com');         // 外部接続（タイトル取得）
     }
     ```

   - 記事編集（`action=update`）を使う場合は Docs のスコープも必要です。上の関数に `try { DocumentApp.getActiveDocument(); } catch (e) {}` の1行を足して承認してください（新規保存分ではドキュメントを作らないため、旧データを編集しないなら不要）
6. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（合言葉で保護する前提。Googleアカウント制限にするとPWAからのfetchが通らないため）
7. 表示された **WebアプリURL**（`https://script.google.com/macros/s/…/exec`）を控える

動作確認: WebアプリURLをブラウザで開き `{"ok":true,...}` が表示されればOK（稼働確認だけは合言葉不要）。

> コードを修正したら「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で更新する（URLは変わらない）。**新しいGoogleサービスを使う変更を入れたときは、再デプロイだけでなく Step 1-5 の承認をもう一度通してください。**

### Step 2: PWA（フロントエンド）のVercelデプロイ

1. [vercel.com](https://vercel.com) にGitHubアカウントでログイン
2. 「Add New…」→「Project」→ このリポジトリ（`knowledge-share-app`）を検索
   - 一覧に出ない場合: インポート画面の「Adjust GitHub App Permissions」（または [GitHubのInstalled Apps設定](https://github.com/settings/installations)）から、VercelのGitHub Appにこのリポジトリへのアクセスを許可する（非公開リポジトリでもデプロイ自体は可能。表示されないのは単にアクセス権の問題）
3. Framework Preset は「Other」のまま、設定変更なしで「Deploy」（ビルド不要の静的サイト。`api/` 配下は自動でServerless Functionとして認識されます）
4. 発行されたURL（`https://….vercel.app`）を控える

> 以後は `main` にプッシュするたび自動デプロイされます。
> 中継API（`/api/knowledge`）を使う場合は、あわせて「[Vercel Serverless Function（Claude検索用API）](#vercel-serverless-functionclaude検索用api)」の環境変数設定も行ってください。

### Step 3: 実機（Pixel 9a）でのインストールと共有シート登録

1. Chromeで Step 2 のURLを開く
2. 初回起動時に設定画面が出るので入力して「保存する」
   - GAS WebアプリのURL: Step 1-7 のURL（**共有先に表示される他アプリのURLではなく、必ずGASのWebアプリURLを入れる**）
   - 合言葉: Step 1-4 で設定した値
3. Chromeのメニュー（⋮）→「**ホーム画面に追加**」→「**インストール**」を選択
   - ※「ショートカットを追加」ではなく「インストール」であること。インストール型で入れると共有シートに登録される
4. インストール後、適当な記事ページで共有ボタン（⤴）→ 共有先一覧に「**ナレッジ**」が出ることを確認
   - 出ない場合: 一覧を左にスクロール／「その他」を開く。それでも無ければ一度アプリを開いてから再確認

### 実機での投稿テスト

1. Chromeで任意の記事を開く → 共有（⤴）→「ナレッジ」
2. 画面上部に「検出したタイトル（参考・共有元より）」と保存対象のURLが表示されることを確認
3. 必要ならメモ欄を編集する（共有テキストが初期値として入っています）／タグを選ぶ
4. カテゴリボタン（例: PC系）をタップして選択状態にする
5. 「この内容で保存」をタップ → 「保存中です」表示を確認
6. スプレッドシート `ナレッジ一覧` に1行追記されていることを確認（タイトル・タグが入っていること）

## 画面の機能

| ヘッダーアイコン | 機能 |
|---|---|
| 📁 | Driveの「ナレッジ」フォルダを新しいタブで直接開く（過去にドキュメント保存した記事の置き場） |
| 📋 | カテゴリ別の保存済み記事一覧を表示。一覧内の検索欄でそのカテゴリを絞り込める（タップで元記事を新しいタブで開く／記事によっては「編集」ボタンが出る。下記の制約を参照） |
| 🔍 | カテゴリを横断したキーワード検索 |
| ⚙ | GAS接続設定・カテゴリの追加/削除/並び替え・タグの追加/削除/並び替え |
| ✕ | アプリを閉じる（ブラウザが `window.close()` を許可しない場合は手動で閉じる案内が出ます） |

### 保存フロー

カテゴリをタップしただけでは保存されません。カテゴリ（必須）・タグ（任意・複数可）・メモ（任意）を選んでから「この内容で保存」を押すと送信されます。メモ欄は共有・手入力どちらのフローでも常に表示され、共有テキストが初期値として入った状態から自由に編集できます。

### 記事の編集

一覧の「編集」ボタンから、タイトル・URL・メモ・タグを編集できます。タグはトグルチップで複数選択でき（新規タグの作成は編集画面からはできず、設定画面のタグ管理で追加してから使います）、開いた時点でその記事の選択中タグがONになります。各記事はスプレッドシートの「ID」列（UUID・自動付与）で一意特定されるため、**すべての記事が編集対象**です。Googleドキュメント保存を行っていた時期の記事（「Driveファイル」列にリンクがある行）は従来どおりfileIdをキーに編集され、ドキュメント本文も同期更新されます。ID列が無い既存シートには、初回アクセス時に列の追加とIDの自動付与（マイグレーション）が行われます（詳細は[ID列のマイグレーションとロールバック](#id列のマイグレーションとロールバック)を参照）。

### キーワード検索

- 対象は **タイトル・メモ・タグ**の部分一致（大文字小文字は区別しない）。**URLは検索対象外**です
- 絞り込みはGAS側（スプレッドシート走査）で行い、結果を50件ずつ返します
- 入力が止まってから300ms後に検索を実行します（連続入力の吸収）
- **タグの複数選択（AND条件）**: 検索窓の下に既存タグ一覧からのチップが並び、タップで複数選択できます。選択した全てのタグを持つ記事のみに絞り込み（AND条件）、フリーテキスト検索と併用した場合は両方の条件を満たす記事のみが対象になります

### PCブラウザからの利用

Androidの共有シート（Web Share Target）はPCでは機能しないため、PCでは共有パラメータ無しで開いたときに表示される**URLの手入力欄**から新規保存します。メモ・カテゴリ・タグ・一覧閲覧・検索・記事編集はスマホと共通で、画面幅600px以上ではレイアウトが横長向けに調整されます（メディアクエリ分岐。スマホ表示は従来のまま）。

## カテゴリ・タグの管理

カテゴリとタグはどちらも固定配列ではなく、GAS側のスクリプトプロパティ（`CATEGORIES_JSON` / `TAGS_JSON`）でJSON配列として動的に管理しています（PWAは起動時にGASから取得）。追加・削除・並び替えは設定画面（⚙）から行え、コード変更もGASの再デプロイも不要です。

### カテゴリ（必須・1件だけ選ぶ）

- **初期値**: LINE WORKS掲示板の構成を踏襲した10件（業務マニュアル／自由掲示板／PC系／DTP系／その他PC学習、スキル／PCニュース／語学系／英語・中国語／レシピ、お店／TOCO/お知らせ）。GASへの初回アクセス時に自動でこの初期値が設定されます
- **並び替え**: ↑/↓ ボタンで表示順を変更できます。並び順はGAS側に保存され、保存画面・一覧画面のカテゴリボタンにも同じ順序で反映されます。新規追加カテゴリは末尾に付きます
- **削除の挙動**: カテゴリ選択肢から外れるだけで、スプレッドシートの過去の行やDrive上の旧ファイルは削除されません（非破壊）
- **改名は未対応**: 名前を変えたい場合は「新しい名前を追加」→「古い名前を削除」で代用してください（過去のデータは旧カテゴリ名のまま残ります）
- **全削除すると初期値に戻ります**: カテゴリを1件も残さない状態にすると、次回の取得時に上記の初期10件が自動で再設定されます（カテゴリは1件以上あることを前提にしているため。タグは0件が正常な状態なので復活しません）
- カテゴリ名の `/` `\` は `・` に置換されます

### タグ（任意・複数選択可）

- **初期値は0件**です。設定画面（⚙）の「タグ管理」から追加して使います（0件のままでも保存できます）
- 保存画面ではチップ状のボタンとして並び、タップで選択/解除を切り替えます
- スプレッドシートの「タグ」列に `, ` 区切りの1セルとしてまとめて記録されます。キーワード検索の対象にもなります
- 一覧・横断検索の各画面でもタグチップから複数選択でき、選択した全てのタグを持つ記事だけに絞り込みます（詳細は[キーワード検索](#キーワード検索)を参照）
- **削除の挙動**: タグ選択肢から外れるだけで、過去の行に書き込まれたタグ文字列は変更されません（非破壊）
- タグ名の `,` は `、` に置換されます（区切り文字との衝突回避）

## Vercel Serverless Function（Claude検索用API）

Claude.ai（`web_fetch`）から、GASの記事検索API（一覧・横断検索・カテゴリ取得）を直接叩けるようにするための中継APIです。GASのWebアプリURLと合言葉(`SHARED_TOKEN`)をClaude.ai側に渡さずに済むよう、Vercel側の環境変数として保持し、リクエストのたびにサーバー側で付与してGASへ転送します。

### 環境変数（Vercelダッシュボードで設定）

値そのものはこのリポジトリ・READMEには記載しません。

| 変数名 | 用途 |
|---|---|
| `GAS_URL` | GAS WebアプリのURL（[Step 1](#step-1-gasバックエンドのデプロイ)でデプロイしたexec URL） |
| `SHARED_TOKEN` | GAS側の `SHARED_TOKEN`（スクリプトプロパティ）と同じ合言葉 |

**設定手順**

1. Vercelのプロジェクトダッシュボード → 「Settings」→「Environment Variables」
2. 「Add New」で `GAS_URL` と `SHARED_TOKEN` をそれぞれ追加（Value欄に実際の値を入力、対象環境は Production 等必要な範囲を選択）
3. 保存後、「Deployments」タブから最新デプロイの「Redeploy」を実行（環境変数は次回デプロイから反映されるため）

### API仕様

```
GET /api/knowledge?action=<list|search|categories>&keyword=<任意>&category=<任意>&offset=<任意>
```

GASの `doGet` にあるクエリパラメータをそのまま転送するだけの中継です（`token` はクライアントから受け取らず、サーバー側で付与）。

| パラメータ | 必須 | 説明 |
|---|---|---|
| `action` | ○ | `list`（カテゴリ内一覧）／`search`（カテゴリ横断キーワード検索）／`categories`（カテゴリ・タグ一覧とDriveフォルダURLの取得） |
| `keyword` | - | `list`／`search` の絞り込みキーワード（タイトル・メモ・タグの部分一致。URLは対象外） |
| `category` | `list`のみ必須 | 対象カテゴリ名 |
| `offset` | - | ページング開始位置（`list`／`search` のレスポンスの `hasMore`/`offset` に従って次ページ取得に使う） |

レスポンスはGASの応答（`{ ok: true, ... }` / `{ ok: false, error: ... }`）をそのまま透過します。

**動作確認URL例**（`<vercelのデプロイURL>` は実際のものに置き換え。token は含めません）

```
https://<vercelのデプロイURL>/api/knowledge?action=categories
https://<vercelのデプロイURL>/api/knowledge?action=search&keyword=Docker
```

エラー時のレスポンス:

- 環境変数(`GAS_URL`/`SHARED_TOKEN`)未設定: HTTP 500
- GASへの通信自体に失敗（ネットワークエラー等）／GASの応答がJSONとして解釈できない: HTTP 502
- GAS側が業務エラー（`ok: false`）を返した場合: HTTP 200 のまま `{ ok: false, error: ... }` を透過（GASのWebアプリはHTTPステータスを持たず常に200で応答するため）

### 既知の制約: Claude.aiのweb_fetchが検索を正しく呼べないことがある

このAPI自体は`curl`等での直接アクセスでは常に正常に動作する（`action`/`keyword`によるフィルタも正しく効く）ことを確認済みだが、**Claude.ai（claude.aiのチャット、`web_fetch`ツール経由）から使うと、意図したクエリ（`action=search&keyword=...`）が実際にはサーバーへ届かず、実在する記事が「見つからない」と誤報告されることが繰り返し確認されている**。

原因の切り分け（2026-07-26実施）:

- Vercelの「Logs」（Function Logs）で実際に届いたリクエストを確認したところ、`web_fetch`からの通信は`action=list`（`category`なし）になっていた、あるいはリクエスト自体が全く記録されない、という事象を複数回observed
- 同じ検索を`curl`で直接叩くと毎回正しい結果が返ることを都度確認済み（コード・データ側の問題ではない）
- Claude.aiの個人設定（カスタム指示）で「`action=search`を使うこと、`list`は使わないこと」を明記しても改善しなかった

**回避策**: Claude.ai（web_fetch経由）での検索がうまくいかない場合は、Claude Code（このリポジトリを開いているセッション）でBashツール経由の`curl`で直接叩いてもらう方が確実。詳細な経緯は `.claude/LESSONS.md`（2026-07-26のエントリ）を参照。

## 設計メモ

- **保存先の構成**: 記事ごとのファイルは作らず、スプレッドシート「ナレッジ一覧」の1行のみを正本とする単層構成。GASはこのスプレッドシートにコンテナバインドされており、`SpreadsheetApp.getActiveSpreadsheet()` で自分自身のバインド先を参照する（スプレッドシートIDをスクリプトプロパティに持つ必要がない）。タイトル列は元記事URLへの `HYPERLINK` 数式にしてあり、シート上でタップすると記事が開く
- **認証**: GASは「全員」公開 + スクリプトプロパティ `SHARED_TOKEN` の合言葉照合による簡易保護。個人利用前提の最小構成（本格的な認証基盤は意図的に持たない）。保存・カテゴリ/タグ変更(POST)だけでなく、**記事一覧・検索・カテゴリ取得(GET)も合言葉必須**（一覧はタイトル・URL・メモといった個人の閲覧記録に近い情報を含むため、WebアプリURLを知られただけでは読めないようにしている。パラメータ無しの稼働確認のみ合言葉不要）
- **CORS**: PWA→GASの通信は、POSTは `Content-Type: text/plain` で送ることでプリフライト(OPTIONS)を回避し（GASはOPTIONSに応答できない）、GETはヘッダを付けないシンプルリクエストとして送る
- **URLの受け取り**: Androidの共有シートはアプリによってURLを `url`/`text`/`title` のどこに入れるかが揺れるため、`shared_url` → `shared_text` → `shared_title` の順で探索。`shared_text` のURL以外の部分は記事タイトルの参考表示とメモ欄の初期値の両方に使う
- **タイトル取得のフォールバック**: 通信失敗・HTTP 4xx/5xx・`<title>` 不在時は og:title → URLそのもの、の順で代替。Content-Typeヘッダ・metaタグからcharsetを判定し、UTF-8以外のページは読み直す
- **Xポストのタイトル切り詰め**: `x.com`/`twitter.com` の個別投稿URL（`/ユーザー名/status/数字`）は、投稿本文がそのままタイトル化されて長くなりがちなため、取得したタイトルが100文字を超える場合は先頭100文字+「…」に切り詰める。プロフィールページ等 `/status/数字` を含まないURLは対象外。既存の保存済みデータには影響しない（新規保存時のみ適用）
- **短縮/リダイレクトURLの解決**: 保存前に `UrlFetchApp`（`followRedirects: false`）で3xxレスポンスの`Location`ヘッダを最大5回まで手動で辿り、実際の記事URLを特定する。解決できない場合は元のURLのまま保存する（エラーにはしない）
- **保存の体感高速化（fire-and-forget）**: GAS側の処理はリダイレクト解決・タイトル取得のための外部アクセスを伴い応答までに待たされるため、PWAは応答を待たずに送信した時点で「保存中です」を表示する。fetchの `keepalive: true`（非対応環境は `navigator.sendBeacon`）により、表示直後にアプリを閉じても送信はOS/ブラウザが完了させる。検知できるのは送信自体の失敗（オフライン等）のみで、その場合はエラー画面を表示する。完了表示は1.2秒後に保存画面へ戻る
- **表示キャッシュ（stale-while-revalidate）**: カテゴリ/タグ一覧と記事一覧（各カテゴリの先頭ページ）を `localStorage` にキャッシュし、画面表示時はまずキャッシュで即描画→裏でGASから最新を取得して差分があれば描き直す。初回（キャッシュ無し）のみ取得完了を待つ。検索中はキャッシュを使わず常にGASへ問い合わせる
- **記事一覧・検索のページング**: 一覧/検索APIは新しい順に50件ずつ返し（`offset` パラメータで続きを取得、`hasMore` で継続有無を返す）、PWAは「さらに読み込む」ボタンで追記表示する。カテゴリ内一覧（`list`）と横断検索（`search`）はGAS側で同じ走査処理を共有し、カテゴリ絞り込みの有無だけが違う
- **カテゴリ・タグのCRUD・並び順**: `PropertiesService`（スクリプトプロパティ）にJSON配列として保存（配列の順序＝表示順）。追加・削除・並び替えはGASへのPOST(`addCategory`/`removeCategory`/`reorderCategories`/`addTag`/`removeTag`/`reorderTags`)で行い、`SHARED_TOKEN` の検証対象にも含まれる。並び替えは「現在の一覧の並べ替えになっているか」（集合が完全一致するか）を検証してから保存する。保存時のカテゴリ・タグはサーバー側でも現在の一覧に存在するかを検証する
- **ルートフォルダIDのキャッシュ**: 📁ボタンが開く「ナレッジ」フォルダを毎回名前検索せず、初回に見つけたIDをスクリプトプロパティに記憶してIDで直接開く。フォルダが削除されていた場合は名前検索で作り直す
- **Sheetsへの書き込み安全策**: タイトル・メモ・カテゴリ・タグ等の自由入力由来のセル値は、先頭が `=` や `+` の場合にアポストロフィを付けて書き込む（GASの `appendRow` は先頭 `=` の文字列を数式として解釈するため、悪意あるページタイトル経由の数式実行を防ぐ）。`HYPERLINK` 数式に埋め込む文字列はダブルクォートをエスケープする
- **一覧画面のXSS対策**: 記事一覧はHTML文字列の結合ではなくDOM API（`createElement` + `textContent`/`href`プロパティ）で描画する（URL内の引用符による属性breakoutを構造的に防ぐ）。hrefに設定する前にURLスキーム（http/https）も検証する
- **メモの重複防止**: Android共有時、共有テキストの「URL以外の部分」がタイトルと同一の文字列になることが多い（共有元がタイトルをそのままテキストに乗せてくるケース）。GAS側で実際に取得したタイトルと完全一致する場合はメモとして保存しない
- **保存済み記事の編集（`action=update`）**: 行の特定キーは **id（ID列のUUID）優先・fileId（GoogleドキュメントのID）フォールバック**。id指定時はSheetsインデックスの該当行（タイトル/URL/メモ）のみ更新し、DocumentApp操作は行わない（新規保存の記事はDocを持たないため）。fileIdのみ指定時は従来どおりSheets行と対応するドキュメント本文の両方を更新する（PWAはfileIdを持つ既存Docs記事にはfileIdを、それ以外にはidを送り分ける）。fileIdはSheetsの「Driveファイル」列のHYPERLINK数式（`getFormulas`で取得）から抽出する。行特定はSheetsインデックスに載っている記事に限定し（一覧に無いid/fileIdは拒否）、無関係なDriveファイルを触らせない。保存日時・カテゴリ・自動抽出された本文・「共有時のURL」行は編集時も保持する。`tags`（配列）は指定時のみタグ列を置き換える（save時のvalidateSaveParams_と同じく現在のタグ一覧に完全一致するタグのみ許可、未登録タグはエラー）。未指定なら既存のタグを保持し、空配列を送ると全クリアする

### ID列のマイグレーションとロールバック

**⚠ この機能を含むPRをマージ・デプロイする前に、必ずスプレッドシート「ナレッジ一覧」のバックアップ（「ファイル」→「コピーを作成」）を取ってください。** マイグレーションは既存シートの列構成を変更する破壊的変更です。

**マイグレーションの内容**（デプロイ後の初回アクセス時に自動実行）:

- ヘッダ行の末尾（H列）に「ID」列を追加する
- ID列が空のデータ行すべてに `Utilities.getUuid()` で一意なUUIDを付与する
- **冪等**: 非空セルは型（文字列/数値）を問わず一切変更しないため、何度実行されても結果は同じ。新規保存の行には保存時点でIDが付与される
- 想定外状態の扱い: ID重複行はマイグレーションでは修復せず、編集時は先頭（最古）の一致行だけが対象になる。ヘッダ行を手動で複製した行はデータ行として扱われUUIDが付与される（従来から記事扱いのため挙動変化なし）

**ロールバック手順**（この変更をマージ後に取り消したい場合）:

1. 該当PRを `git revert` して main へマージし、GASエディタへ旧コードを貼り直して再デプロイする
2. スプレッドシートの「ID」列（H列）は**削除しなくてもよい**（旧コードは末尾列を参照しないため残しても無害）。完全に元へ戻したい場合のみH列を手動削除する
3. マイグレーション後に新規保存した記事はID列以外は従来と同じ形式のため、データの巻き戻しは不要（バックアップコピーは万一の保険）

### 保存形式の変遷（経緯）

1. **プレーンテキスト/Markdown（`.md`）**: 記事ごとにDriveへファイルを作成していた
2. **Googleドキュメント**: クラウド版Claudeの Google Drive 連携が text/markdown・text/plain を読み込めず、AIがファイルを直接開けないことが実運用で判明したため `DocumentApp` ネイティブ形式へ変更
3. **現行（Sheetsインデックスのみ）**: ドキュメント作成とページ本文の自動抽出を廃止。本文抽出には、セマンティックタグの無いサイトで本文以外が混入する・JSで動的描画するサイト（X等）では本文がほとんど取れない、という精度上の限界があった。検索・一覧はスプレッドシートで完結するため、AI(Claude)にはスプレッドシートを読ませる運用に切り替えた

各段階で保存したデータはそのまま残るため、Drive上には `.md` ファイルとGoogleドキュメントが混在している場合があります（いずれも自動移行はしません）。
